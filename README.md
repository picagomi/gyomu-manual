# NagomiResort マニュアル（写真でつくる業務マニュアル）

現場の写真をアップするだけで、スマホで読める手順書になるアプリ。
インストール不要・オフライン可・データは端末内（IndexedDB）に保存。

**公開URL → https://manual-biz.com/**
スマホでこのURLを開き、「ホーム画面に追加」するとアプリとして起動できます。

## 使い方
### ひな形からつくる（いちばん早い）
一覧の「📋 ひな形」から **停電時復旧マニュアル**（7拠点＋12手順が入った状態）を1タップで作れます。
文章は「型」なので、実際の設備・連絡先に合わせて直し、分電盤などの写真を後から足してください。
**給湯器の運転（写真つきの実例）** は、実際の屋外給湯器と PURPOSE リモコン MC-100 の写真が入った見本です
（`samples/kyutouki-mc100.json` を読み込みます）。作りかたの参考にどうぞ。
「（空）複数拠点の対応マニュアル」は7拠点だけ入った空の状態で、日常点検や開店準備を自分で書くとき用です。

### 写真からつくる
1. 「📷 写真からつくる」で写真を選ぶ（カメラ撮影でもOK・複数枚可）
2. タイトルを付ける（例：停電時復旧マニュアル）
3. **対象の場所を登録**（受付・コテージ・ヴィラ・カフェ・ドッグスパ・ドッグラン・753カフェ …複数OK）
4. 写真ごとに「見出し／作業内容／⚠️注意点」を入力 → 保存
5. 以後は「更新する」で追記。保存のたびに更新メモ付きで**改訂履歴（v1, v2…）**が残る

## 複数の場所を回る作業（停電対応など）

    一覧で「停電時復旧マニュアル」をタップ
        ↓
    ① 場所えらび画面（受付 / コテージ / ヴィラ / カフェ / …のボタンが並ぶ）
        ↓  場所をタップ
    ② その場所の作業手順（全場所 共通の手順＋その場所だけの手順）
        ↓  「✓ ○○ 済にする」
    ① に戻る（その場所に「✓ 済 12:40」が付き、進捗が進む）
        ↓  全部おわると
    🎉 おつかれさまでした！（対応ログに完了日時を記録）

- 場所を**2か所以上**登録すると、この2段構えの画面になります（1か所以下なら手順がそのまま出ます）
- 手順ごとに「**全場所 共通** / **この場所だけ**」を指定できます（例：分電盤の位置＝共通、受付のPOS再起動＝受付だけ）
- 画面下にはつねに **進捗（3/7 か所 完了・残りの場所）** が出ます
- 次の対応に使うときは「対応状況をリセット」（対応ログは残ります）
- 対応チェックは改訂履歴とは別扱いで、マニュアル本文のバージョンは上がりません
- 「すべての手順をまとめて見る」で全場所ぶんを通しで確認・PDF化できます

- 検索：タイトル・場所・手順本文をまとめて検索
- 共有：本文をコピー／スマホの共有シート、「印刷 / PDF」でPDF化
- バックアップ：右上「⋯」→ JSONで書き出し／読み込み（写真も含む）

## ローカルで開く
```
cd ~/Downloads/code/gyomu-manual
python3 server.py 8790
```
→ ブラウザで http://localhost:8790

スマホから見るときは同じWi-Fiで `http://<MacのIP>:8790`。
Safari／Chromeの「ホーム画面に追加」でアプリのように起動できます。

## 独自ドメイン（設定済み）
`manual-biz.com`（Xserverドメインで取得）を GitHub Pages に割り当て済みです。

- ネームサーバー：`ns1〜ns3.xdomain.ne.jp`（Xserverアカウントの「DNSレコード設定」で管理）
- DNS：`manual-biz.com` の A レコード4本（`185.199.108〜111.153`）＋ `www` の CNAME → `picagomi.github.io`
- リポジトリ直下の `CNAME` ファイルにドメイン名。**このファイルを消すとドメインが外れます**
- HTTPS強制ON（Let's Encrypt の証明書を GitHub が自動更新）
- `http://` / `www.` / 旧URL `picagomi.github.io/gyomu-manual/` はすべて `https://manual-biz.com/` へ自動転送

<details><summary>切り替え手順の記録（別ドメインに移すときの参考）</summary>

アプリ内のファイル参照はすべて**相対パス**なので、URL が変わってもコードの修正は不要です。
（`manifest.json` は `start_url: "./index.html"` / `scope: "./"`、`sw.js` のキャッシュも相対パス）

ドメインが取れたら、次の3ステップだけで切り替わります。

1. **DNS を設定**（サブドメイン推奨。例：`manual.example.jp`）
   - サブドメインの場合：`manual` の **CNAME** レコード → `picagomi.github.io`
   - 独自ドメインのルート（`example.jp`）を使う場合：**A** レコードを4つ
     `185.199.108.153` / `185.199.109.153` / `185.199.110.153` / `185.199.111.153`
2. **リポジトリのルートに `CNAME` ファイルを追加**（中身はドメイン名1行だけ）してpush
   ※ GitHub の Settings → Pages でドメインを入力しても同じファイルが作られます
3. Settings → Pages で **Enforce HTTPS** にチェック（証明書の発行に数分〜1時間）

切り替え後、旧URLは新ドメインへ自動転送されます。
</details>

### ⚠️ 切り替え時のデータ引き継ぎ
マニュアルのデータは**ブラウザにアドレス（URL）ごとに保存**されるため、URLが変わると
**新しいアドレスでは空**になります。引き継ぎ手順：

1. 旧アドレスで開く → 右上「⋯」→ **バックアップを書き出す（JSON。写真も含まれます）**
2. 新アドレスで開く → 右上「⋯」→ **バックアップを読み込む**

そのため、**スタッフへの本格的な配布はドメイン確定後**がおすすめです。
（将来 Firebase で共有化すると、データはサーバー側に置かれるのでURL変更の影響を受けなくなります）

## 公開（GitHub Pages）
`main` ブランチのルートを GitHub Pages で公開しています。
更新するときは編集して push するだけで、1〜2分後に公開URLへ反映されます。

```
cd ~/Downloads/code/gyomu-manual
git add -A && git commit -m "説明" && git push
```

## 注意
データは**その端末のブラウザ内だけ**に保存されます。複数人で同じマニュアルを共有するには、
サーバー（Firebase / Supabase など）の追加が必要です。バックアップJSONの受け渡しでも共有できます。
